# Reference Scout 单次编码 A/B 结果

测试日期：2026-09-15。模型与 DSH 版本相同，两个目录来自同一份 seed，收到完全相同的 `AsyncTtlCache<K, V>` 任务。Agent 编码期间只能看到 4 个公开测试；结束后才注入 10 个隐藏验收测试。原始机器数据见 `results.json`。

| 指标 | 无插件 | Reference Scout | 差异 |
| --- | ---: | ---: | ---: |
| 隐藏测试 | 9 / 10 | 8 / 10 | -1 个通过项 |
| TypeScript 类型检查 | 通过 | 通过 | 持平 |
| 公开测试 | 11 / 11 | 4 / 4 | 均通过；无插件组违反任务约束并新增了 7 个测试 |

“三项 token 计数之和”只用于比较这两次 DSH session 的模型流量，不代表 API 账单；缓存读取通常与未缓存输入的计价不同。

## 质量判定

- 无插件组唯一失败：接受了 `ttlMs = 0`，而任务要求非法 TTL 抛错。
- 插件组失败两项：同样接受 `ttlMs = 0`；另外把 loader 放进了下一个 microtask 才调用，因此调用 `get()` 后同步观察时 loader 尚未启动。
- 两组都通过类型检查和其可见测试。按隐藏测试计分，本次样本中插件没有提升质量，反而从 90% 降到 80%。

## 检索链路判定

修复后的服务会把 `AsyncTtlCache` / `async-ttl-cache` 拆成 `async`、`ttl`、`cache`，并识别 `lru`；精确结果全部被许可证策略过滤时，会继续用 `"cache" "lru" language:TypeScript` 回退。真实 GitHub API 验证中该查询有 42 个原始结果，完整服务最终状态为 `completed`，并固定了 3 个候选的 commit SHA。正式插件组 session 中也观察到了 `research_reference` 调用及参考简报。

## 结论与限制

本次插件组减少了步骤、耗时及所有主要 token 计数，但没有提高隐藏测试质量。token 降幅的一部分来自无插件 Agent 自行新增测试并反复修改，而插件 Agent 遵守了“不修改测试”的约束；不能把全部差异归因于检索插件。单次运行还包含模型随机性，因此该结果只能说明：当前插件在这个小任务上展示了明显的 token/时间优势，但尚无编码质量提升证据。若要形成发布宣传结论，至少应扩展到多任务、多次重复，并使用盲测评分。
